# PRD PoC 表述更新清单

来源：`/media/lemonhdl/Shared/Software_Engineering/ARY/ary-grs-001-prd.md`

用途：先把 PRD 中所有依赖 PoC 最终实现版本的表述集中列出。等最终 PoC 演示版本确定后，再统一修改主稿，避免现在一处处改完又和最终实现不一致。

行号基于 2026-06-07 当前版本，仅用于定位。

## 更新原则

- 只根据最终可运行 PoC 写，不按旧设想写。
- 页面路径、页面数量、提交入口、状态变化、验证命令必须和最终演示一致。
- 如果最终 PoC 没有真实实现“沙箱”“排队”“转发”，PRD 中不能把它写成已实现能力，只能写成概念链路或后续替换方向。
- 2026-06-07 已先将沙箱、排队、Riding Record 存储、自动抓取、防造假、过强安全承诺等非 PoC 口径收紧；最终 PoC 确认后仍需重写 §7 和同步页面路径、验证命令。
- 不在用户可见页面暴露内部路径、服务进程、mock、JSON、API、文件名等实现细节；PRD 可以说明 PoC 简化实现，但要和产品 UI 表达分开。

## 最终 PoC 确认后需要收集的信息

更新 PRD 前，先确认以下事实：

1. 最终 PoC 目录。
2. 启动平台的命令。
3. 启动 Organizer 或数据可用性服务的命令。
4. 自动验证命令与真实通过输出。
5. 页面路径清单。
6. 演示脚本步骤。
7. 提交入口和提交内容。
8. Records / Replay 的解锁条件。
9. 页面中实际展示的状态文案。
10. 哪些能力是已实现，哪些只是正式系统设计。
