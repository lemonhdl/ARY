内容节点落地顺序

这里沿用源文档内容路径，只说明哪些内容节点先成立、哪些可以并行；成员只作为后置责任挂载，不作为路径起点。

第 0 步：定位与对象先固定 不可跳过
A 产品定位与 Display Scope
  • Jumbotron 是公开大屏容器。
  • 展示赛事摘要，不展示完整 Session。
  • MVP 只保留 race_live / Race Live View。
B 核心信息对象
  • Competition、Racing Entry、KPI。
  • Riding Message、Attention Item。
  • Track Template、Racing Position、Motion State。
两条源文档输入链路并行准备
第 1 步：数据链路与资产链路并行 并行，但必须共享 TrackProfile 和 progress 语义
B DCR RaceSnapshot → Jumbotron Adapter
  • 选择进度字段，默认 roundProgress。
  • 映射 entries、messages、risks。
  • 输出 runtime 输入快照。
C AI / Design Background → Calibrator
  • 导入底图和候选 Profile。
  • 编辑 centerline、lanes、checkpoints、zones。
  • 导出 track.profile.json。
E Validation 规则准备
  • Track Profile Validation。
  • Runtime Validation。
  • Visual Validation。
汇合到 track-runtime
第 2 步：track-runtime 成为共享计算层 Jumbotron 和 Calibrator Preview 都必须复用
B 位置与动画规则
  • roundProgress → s → sampled point。
  • 计算 tangent、normal、lane offset。
  • 输出 HorsePose 和 motion state。
C Calibrator Preview
  • 用 scrubber 验证单马 0 到 100。
  • 用多马预览验证 lane offset。
  • 复用同一套 track-runtime。
进入 Race Live View 展示
第 3 步：Race Live View IA 与现场规则落地 展示层依赖 Adapter、Track Profile 和 runtime 已成立

  • Header、KPI Strip、Main Track Area。

  • TOP3、Attention Item。

  • centerline、sampled points、lane offsets。

验证后收口
第 4 步：三类验证与 MVP 验收 先验收内容路径，再收口文档和提交范围
E 验证闭环
  • Track Profile、Runtime、Visual 三类验证。
  • 确认马在赛道上、弯道自然、气泡不遮挡。
  • 确认 stale、越界、profile mismatch 可见。
A 交付文档
  • README、过程记录、验收口径。
  • 说明源文档覆盖范围。
  • 提交推送只在用户明确要求后进行。

三条主链路

事实来源到马匹位置
  • TrackProfile 定义 centerline、lanes、checkpoints。
  • roundProgress 映射为 normalized s。
  • sample centerline，计算 tangent、normal、lane offset。
  • 输出 HorsePose.x/y/rotation/s。
RaceSnapshot 到大屏展示
  • RaceSnapshot 进入 Jumbotron Adapter。
  • 输出 RacingEntrySnapshot[]、RidingMessageSnapshot[]、AttentionItem[]。
  • Race Live View 展示 TOP3、KPI、马匹、气泡、ticker。
Calibrator 到可复用资产
  • 导入 background.webp 和候选 Track Profile。
  • 编辑 centerline、方向、起点、lanes、checkpoints。
  • Preview 复用 track-runtime。
  • 导出可被 Jumbotron Preview 直接使用的 track.profile.json。

并行关系与顺序约束

内容节点 / 链路 关系 前置依赖 不可跳过的检查
Display Scope、核心信息对象、数据链路、资产链路、验证规则 可并行 产品定位与展示边界 共享同一套 Jumbotron、Race Live View、TrackProfile、roundProgress 语义。
TrackProfile → track-runtime → Runtime Validation 有顺序 核心信息对象与 Track Template 字段 不能先写死 UI 坐标再补 runtime；必须从 Track Profile 采样。
AI / Design Background → Track Profile Calibrator → track.profile.json 有顺序 TrackProfile schema 与资产范围 Calibrator Preview 必须复用 track-runtime，不能另写一套预览逻辑。
DCR RaceSnapshot → Jumbotron Adapter → Race Live View 有顺序 runtime 输入快照、track-runtime、Track Profile 资产 必须同时接入资产、runtime、Adapter、UI skeleton。
Debug Mode、Riding Message、TOP3、Motion State 可并行 Race Live View 主链路跑通；Motion State 依赖 track-runtime 增强项不能违反展示边界，不能伪造连续推进。
Track Profile Validation → Runtime Validation → Visual Validation → MVP 验收 有顺序 track.profile.json、Race Live View、Debug Mode、现场展示规则 先资产冻结，再端到端验收，再收口文档，最后在用户明确要求后提交推送。

必须保留的设计边界

数据与位置

  • track.profile.json 是运行时事实来源。
  • background.webp 只负责视觉，不负责语义。
  • 位置来自 roundProgress 和赛道几何。
  • 补间在 s 轴上进行，不直接在 x/y 上补间。

展示边界

  • Jumbotron 展示摘要，不展示完整 Session。
  • 不展示完整终端日志、复杂代码 diff、长文本评论流。
  • MVP 只保留 race_live，不扩展独立第二大屏。
  • TOP3 只表达实时领先关系，不变成独立看板。

工具与验证

  • Calibrator 是设计时资产生产工具，不是运行时 UI。
  • Calibrator Preview 必须复用 track-runtime。
  • AI 只参与候选资产生产，不参与运行时可信计算。
  • 验证分为 Track Profile、Runtime、Visual 三层。
