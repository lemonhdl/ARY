原文 + 解释 Calibrator Track Profile Jumbotron GRS002

一、评审标准：Calibrator 是 20 分主项，不是可选装饰

来源：ARY GRS 002 Jumbotron 评审标准.md

原文
## 3. Calibrator 与赛道资产生产｜20 分 评审重点：团队是否证明了赛道资产可以被生产、校准、验证和复用。
ARY GRS 002 Jumbotron 评审标准.md:182-184
解释

这里直接给了 20 分。Calibrator 不是附属说明，而是和 Race Live View 同级的重要评分项。评委看的是能不能把赛道资产从底图变成可运行 profile，并证明这个 profile 能复用。

原文
评分要点： - 是否提供 Track Profile Calibrator 或等价校准工具； - 是否能导入或使用赛道底图； - 是否能创建、编辑或导入 centerline points； - 是否能设置起点 / 终点、方向、闭合路径； - 是否能配置 lane offsets； - 是否能配置 checkpoints； - 是否能通过 scrubber 或 preview 预览单马 0% → 100% 运行； - 是否能预览多马运行，证明 lane offset 可用； - 是否能 Validate 并展示校验结果； - 是否能 Export `track.profile.json`； - 是否能解释 `track.profile.json` 中的关键字段； - 是否能说明 AI 生成底图与人工校准之间的关系； - 是否能提交至少一套可用赛道资产。
ARY GRS 002 Jumbotron 评审标准.md:186-200
解释

这一组是最直接的验收清单。最低要证明导入底图、编辑中心线、设置起终点和方向、配置 lanes/checkpoints、预览单马和多马、Validate、Export。只展示一张赛道图或只写说明，都不够。

原文
高分作品特征： > Calibrator 不是摆设，而是真正让一张视觉底图变成可运行赛道资产；评委能看到从底图、路径校准、预览、验证到导出 profile 的完整流程。
ARY GRS 002 Jumbotron 评审标准.md:202-204
解释

高分不只看有没有入口。要让评委看见一条完整链路：底图进入工具，路径被校准，马能跑，校验有结果，最后导出 profile，并能回到 Jumbotron 使用。

二、硬性门槛：不能完全没有校准流程

来源：ARY GRS 002 Jumbotron 评审标准.md

原文
### 2. 必须有 Calibrator 或可验证的赛道校准流程 作品必须说明并演示赛道底图如何变成可运行的语义赛道资产。 至少需要体现： - 导入或使用一张赛道底图； - 定义或编辑 centerline points； - 设置起点 / 终点或方向； - 配置 lane offsets； - 预览单马或多马运行； - 导出或展示 `track.profile.json`； - 说明 Jumbotron 如何使用该 profile。 Calibrator 可以是完整工具、简化工具、开发者工具页，或具备清楚操作流程的 PoC，但不能完全没有赛道校准过程。
ARY GRS 002 Jumbotron 评审标准.md:38-52
解释

这是入围门槛，不是加分项。允许是简化工具或开发者工具页，但必须能演示赛道如何从视觉底图变成语义 profile。没有校准流程会直接影响基本评价。

原文
出现以下情况，原则上不能获得高分，严重时可直接判定不合格： 2. 没有 Calibrator，也无法说明赛道资产如何被校准为可运行 profile； 5. 赛马位置、排名、气泡和风险标记全部写死在图片或设计稿中； 6. 无法解释 `track.profile.json` 或等价赛道语义资产的作用；
ARY GRS 002 Jumbotron 评审标准.md:343-353
解释

这里说明了红线：没有 Calibrator 或没有可解释的校准流程，不能靠静态设计稿过关。马、排名、气泡、风险标记如果都写死在图里，也会被认为没有回答赛题。

三、短视频与提交物：必须讲清怎么用

来源：ARY GRS 002 Jumbotron 评审标准.md

原文
作品必须提交一段短视频，用于说明 Jumbotron 和 Calibrator 的使用。 短视频建议 3–5 分钟，至少应包含： 4. Calibrator 导入或使用赛道底图； 5. Calibrator 编辑 / 校准路径、预览马匹运行、Validate、Export； 6. 导出的 `track.profile.json` 如何被 Jumbotron 使用； 7. 哪些数据是真实接入，哪些数据是 mock，哪些部分仍是 PoC。
ARY GRS 002 Jumbotron 评审标准.md:68-78
解释

短视频不能只拍大屏效果。需要拍 Calibrator 的关键操作：导入底图、校准路径、预览、Validate、Export，再说明导出的 profile 如何进入 Jumbotron。

原文
正式提交建议包括： 1. **作品说明文档** - Calibrator 使用流程； - 数据与资产说明； - PoC 边界与未实现部分。 3. **短视频** - 展示 Calibrator； - 展示 profile 导出与运行时加载； - 说明关键技术路线。 4. **赛道资产** - `background.webp` 或等价底图； - `track.profile.json`； - `preview.png`，若有； - `notes.md` 或校准说明； - `source.prompt.md`，若使用 AI 生成底图。
ARY GRS 002 Jumbotron 评审标准.md:98-124
解释

提交材料要有三类证据：文档讲流程，视频展示操作，资产目录交付底图和 profile。未实现部分也要诚实说明，避免把候选资产说成正式冻结资产。

四、运行时关系：Calibrator Preview 必须和 Jumbotron 共用逻辑

来源：ARY GRS 002 Jumbotron 评审标准.md 与 Jumbotron子系统定义.md

原文
- 是否保证 Calibrator Preview 与 Jumbotron 使用同一套或同一逻辑的 track-runtime； - 是否避免直接在 x/y 上粗暴补间导致马匹穿越弯道。
ARY GRS 002 Jumbotron 评审标准.md:223-225
解释

Calibrator 不是另做一套假预览。它预览出来的马匹位置，应该和 Jumbotron runtime 的路径采样、lane offset、horse pose 逻辑一致。这样导出的 profile 才可信。

原文
关键原则：Calibrator 预览必须复用 `track-runtime`，不能另写一套预览逻辑。 track.profile.json → track-runtime ├── Jumbotron / Race Live View └── Track Profile Calibrator Preview
Jumbotron子系统定义.md:119-126
解释

这是架构约束。Calibrator 和 Jumbotron 应该在 track-runtime 汇合。评审时要说明同一个 track.profile.json 如何同时支撑校准预览和运行时大屏。

六、MVP 与 P1：哪些是当前必须，哪些是增强

来源：Jumbotron子系统定义.md

原文
### 4.1 Calibrator MVP 功能 1. 导入底图； 2. 加载 / 创建 Track Profile； 3. 添加、删除、拖拽 centerline points； 4. 平滑路径预览； 5. 闭合路径； 6. 一键反转路径方向； 7. 设置起点； 8. 配置 lane offsets； 9. 配置 checkpoints； 10. 通过 scrubber 预览一匹马从 0% 到 100%； 11. 预览多匹马； 12. Validate； 13. Export JSON。

解释

MVP 的重点是路径、方向、起终点、lanes、checkpoints、预览、校验和导出。拖拽点位也被列在 MVP 中，如果当前只支持 JSON 编辑和添加删除，需要在边界说明里标出。

原文
### 4.2 Calibrator P1 功能 1. 气泡区域编辑； 2. no bubble zone 编辑； 3. 风险区域编辑； 4. AI 候选点导入； 5. 自动检测尖角； 6. 自动分配 lanes； 7. 导出 debug-preview.png； 8. JSON diff preview。
Jumbotron子系统定义.md:267-276
解释

P1 是增强项。气泡区、no-bubble 区、risk 区的画布编辑，AI 候选点导入，自动 lanes，debug-preview.png 都可以作为后续计划；JSON diff 如果实现了，可以作为加分证据。

七、资产生产与冻结：Calibrator 要服务最终资产包

来源：Jumbotron子系统定义.md

原文
### 8.1 AI-assisted Asset Pipeline AI 不参与运行时可信计算，只参与设计时候选资产生产。 推荐流程： 1. 编写赛道视觉 prompt 2. AI 生成 16:9 赛道底图 3. AI 输出候选 centerline points 4. 导入 Calibrator 5. 人工校准路径 6. 预览多马运行 7. Validate 8. Export 9. 提交资产
Jumbotron子系统定义.md:523-540
解释

AI 可以帮忙生成底图和候选点，但可信几何必须经过人工校准和 validation。Calibrator 的价值在于把 AI 候选变成可检查、可导出的运行时资产。

原文
### 8.3 资产冻结规则 一个 track asset 进入 DCR 前必须满足： 1. 通过 schema validation； 2. 通过 geometry validation； 3. 通过 0% → 100% 单马预览； 4. 通过至少 8 匹马多马预览； 5. 没有明显跑出赛道； 6. checkpoint 显示正确； 7. 在 16:9 大屏下视觉稳定； 8. profile 与 background 一起提交。
Jumbotron子系统定义.md:562-573
解释

导出 JSON 还不等于正式冻结。正式资产要经过 schema、geometry、单马、多马、视觉稳定性和背景配套检查。当前如果只导出 candidate，就要说明还没有完成正式冻结。

八、Validation：导出前必须能检查

来源：Jumbotron子系统定义.md

原文
### 9.1 Track Profile Validation 导出前必须校验： - schemaVersion 存在 - trackId 存在 - viewBox 合法 - background 存在 - centerline points 数量足够 - closed track 至少 4 个点 - open track 至少 2 个点 - direction 合法 - startFinish.s 在 0~1 范围内 - checkpoints.s 均在 0~1 范围内 - lanes 至少 1 条 - lane offsets 不重复 - path length 大于最小阈值 - sampled path 无明显 NaN / Infinity - 相邻采样点距离无异常跳变 - 曲率或转角超过阈值时给 warning
Jumbotron子系统定义.md:577-600
解释

Validation 是评分证据。它要覆盖字段完整性、几何合法性、路径质量和异常 warning。只说“可以导出”不够，需要展示校验结果。

原文
### 9.3 Visual Validation Calibrator 提供人工确认： - 马是否跑在赛道上 - 弯道处是否自然 - 多马是否严重重叠 - 气泡是否遮挡标题 / KPI / 顶部区域 - checkpoint 是否符合视觉语义
Jumbotron子系统定义.md:615-625
解释

不是所有问题都能自动判断。Calibrator 还要给人工确认入口，尤其是弯道自然、多马重叠、气泡遮挡和 checkpoint 语义。这些应在视频或审阅截图中体现。

九、MVP 验收口径：Calibrator 和 Jumbotron 要连起来

来源：Jumbotron子系统定义.md

原文
## 12. MVP 验收口径 Jumbotron 子系统 MVP 成立，需要满足： 1. `track.profile.json` 能描述一条完整赛道； 2. Calibrator 能从候选路径微调出可用赛道； 3. Calibrator 导出的 profile 能被 Jumbotron Preview 直接使用； 4. Calibrator 和 Jumbotron Preview 使用同一套 `track-runtime`； 5. 一匹马可按 0% → 100% 沿赛道移动； 6. 多匹马可通过 lane offset 同时展示； 7. 马匹在弯道处方向自然； 8. stale / blocked / pit_stop / takeover / finished 状态可表达； 9. 解释

最终不是单独评一个工具页面，而是看 Calibrator 导出的 profile 能否进入 Jumbotron Preview，并由同一套 runtime 驱动马匹、状态和消息。至少 2 条可用示例赛道资产也是这里的明确要求。

十、信息架构文档的间接约束

来源：Jumbotron信息架构.md

原文
## 8. MVP 落地约束 1. Jumbotron 是大屏容器，MVP 只包含 `race_live` 显示范围。 2. Race Live View 默认用 `roundProgress` 映射赛道位置。 3. 赛道底图只负责视觉，不负责语义。 4. 赛道几何必须显式存在，不能从图片反推。 5. 马匹位置由进度和赛道几何派生，不把设计稿 `x / y` 当作业务事实。 6. 动态表现由状态机驱动，不做真实物理仿真。 7. 数据更新慢时，使用短时间补间、原地动效、气泡和高亮，不伪造连续推进。 8. 不包含独立第二大屏模式、项目主表或多维排行需求。 9. Jumbotron 只展示摘要，不承载完整 Session、完整日志或复杂分析。
Jumbotron信息架构.md:485-495
解释

这份文档没有单独给 Calibrator 打分，但它限定了校准工具的必要性：赛道几何必须显式存在，不能从图片反推；马匹位置必须由进度和几何派生，不能把设计稿坐标当事实。

一句话汇总

必须有

Calibrator 或等价可验证校准流程，能说明底图如何变成 track.profile.json。

20 分主项

评分看资产能否生产、校准、验证、导出和复用。

关键证据

导入底图、编辑 centerline、配置 lanes/checkpoints、单马和多马预览、Validate、Export。

高分条件

Calibrator 不是摆设，要展示从底图到路径校准、预览、验证、导出 profile 的完整流程。

架构红线

Calibrator Preview 和 Jumbotron 必须共用或复用同一套 track-runtime 逻辑。

仍要说明边界

如果只有 MVP，要明确 P1 和正式资产冻结流程哪些还没完成。
