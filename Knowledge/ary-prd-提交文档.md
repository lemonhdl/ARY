# 2 角色与用例

| 角色 | 职责 | 核心用例 |
| --- | --- | --- |
| Organizer | 定义 Race，决定公开范围，保留受限数据 | 发布赛事信息，提供可公开的 Record 摘要 |
| Rider / 参赛者 | 查看赛事，提交答案，参与 Agent Riding Race | 浏览 Race，查看 Record，提交答案 |
| 评审 / Viewer | 理解平台价值和过程证据 | 查看 Record Detail 和 Replay |
| ARY 平台 | 组织和展示公开内容 | 展示 Race、Riding Record、Replay 和提交状态 |

---

# 3 功能需求

| 模块 | 需求 | 验收点 |
| --- | --- | --- |
| Race 首页 | 展示已发布赛事信息和当前状态 | 首页能说明这是 ARY Genesis Race Series |
| Riding Records | 展示 Agent Riding Record 列表 | 每条 Record 有标题、摘要、标签和入口 |
| Record Detail | 展示一次 Riding 的关键步骤 | 能看到 Prompt、Agent Output、Steering 和 Riding Signal |
| Replay | 按事件流回放 Riding 过程 | 评审能跟随事件理解 Rider 如何驾驭 Agent |
| 提交与评测状态 | 参赛者提交后显示本次状态 | 未提交无结果；数据不可用显示缺失；数据可用显示结果 |
| 数据边界 | 平台不展示未公开材料 | 页面不出现内部路径、文件名、版本指纹、JSON 快照或服务请求细节 |

---

# 4 数据需求与安全机制

数据安全不是“平台没有数据库”。关键是平台不保存也不展示具体场景中被定义为受限的完整数据。
数据安全不是“平台没有数据库”。关键是平台不保存也不展示具体场景中被定义为受限的完整数据。

| 数据类型 | 归属 | ARY 是否展示 | 机制 |
| --- | --- | --- | --- |
| 完整 Race 私有定义 | Organizer | 否 | 数据不进入平台公开内容 |
| 完整协作原文 | Organizer | 否 | 只生成可公开摘要 |
| Riding Record 摘要 | Organizer 主动披露 | 是 | 公开内容展示 |
| 回放事件 | Organizer 主动披露 | 是 | 按关键事件组织 |
| 参赛者提交 | 参赛者 | 仅展示本次提交状态 | 受保护存储或权限控制 |
| 评测状态 | 本次提交产生 | 是 | 显示缺失或完成，不暴露内部处理细节 |

# 5 非功能需求

可理解性数据边界可演示性
可理解性
## 可理解性
- 页面面向参赛者和评审。
- 不展示 debug 信息。
- 主线不偏向普通 OJ。
数据边界
## 数据边界
- 受限数据不进入公开页面。
- 提交后才显示状态。
- 数据不可用时不能继续给结果。
可演示性
## 可演示性
- 路径短。
- 点击顺畅。
- 每个页面都有明确证明点。

# 6 验收标准

| 类别 | 验收标准 |
| --- | --- |
| 产品主线 | Race、Riding Record、Record Detail、Replay 构成完整展示路径。 |
| Agent Riding | Record 详情能体现 Prompt、Agent Output、Steering 和过程复盘。 |
| 提交触发 | 未提交时不显示评测结果，提交后才进入评测状态。 |
| 数据缺失证明 | 数据不可用时页面显示缺失，数据可用时显示本次结果，再次不可用后重新缺失。 |
| 页面可交付性 | 页面不暴露内部路径、文件名、版本指纹、服务请求、终端说明或 JSON 快照。 |

---

# 7 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 被理解成普通评测网站 | 削弱 ARY 平台价值 | 突出 Riding Record、Detail 和 Replay |
| 数据安全只停留在口头说明 | 证明力不足 | 使用提交前后和数据可用性变化做实验性证明 |
| 页面暴露内部实现 | 交付感下降 | 页面只展示用户可理解状态，内部说明放入开发文档 |
| 范围过大 | PoC 难以完成 | 只实现能支撑证明点的页面和流程 |
