# D-Data 提交 d277698 复审

审查对象：`d277698` (`data: 新增 D-data 数据角色交付物`)

结论：D-data 这次交付本身**质量明显高于纯样例文件交付**。它不仅给了 `authority-mock.json`，还附带了生成器、关系镜像、schema、seed 和不变量校验，`python generate.py` 与 `python manage.py verify` 在本地都能跑通，说明交付内部是自洽的。但它**还没有真正接入当前程序壳**：仓库当前装配链路仍然没有把这份交付当成运行时唯一权威 mock 使用，所以从“当前仓库可运行产品壳”的角度，d-data 的主价值还没有被消费到位。

## Findings

### 1. 高优先级：D-data 明确声明 `deliverables/d-data/authority-mock.json` 是运行时主入口，但当前装配链路仍然没有消费它

- D-data 的 handoff manifest 明确写了 `authority-mock.json` 是“第一轮唯一权威 mock”，并要求让 `runtime-data/authority-mock.json` 来源于本文件，见 [deliverables/d-data/handoff.manifest.json](../deliverables/d-data/handoff.manifest.json#L107)。
- 对接说明也把 [deliverables/d-data/authority-mock.json](../deliverables/d-data/authority-mock.json) 定义成运行时主入口，并明确说明应由 E 的 setup/assemble 消费，见 [deliverables/d-data/data-mapping-notes.md](../deliverables/d-data/data-mapping-notes.md#L12), [deliverables/d-data/data-mapping-notes.md](../deliverables/d-data/data-mapping-notes.md#L13) 和 [deliverables/d-data/data-mapping-notes.md](../deliverables/d-data/data-mapping-notes.md#L31)。
- 但当前 [scripts/assemble.js](../scripts/assemble.js#L6), [scripts/assemble.js](../scripts/assemble.js#L13) 和 [scripts/assemble.js](../scripts/assemble.js#L18) 仍然只读取 [runtime-data/authority-mock.json](../runtime-data/authority-mock.json#L3)，而这个运行态文件目前仍是 bootstrap 占位数据，不是 D-data 生成物。
- 实测运行 `node scripts/assemble.js` 后，产出的 [runtime-data/assembled-view.json](../runtime-data/assembled-view.json#L6) 和 [runtime-data/assembled-view.json](../runtime-data/assembled-view.json#L12) 里仍然只有两场赛事；而 D-data 交付的权威 mock 至少包含 `smart-investment-analyst`、`works`、`results`、`caStatuses`，见 [deliverables/d-data/authority-mock.json](../deliverables/d-data/authority-mock.json#L57), [deliverables/d-data/authority-mock.json](../deliverables/d-data/authority-mock.json#L429), [deliverables/d-data/authority-mock.json](../deliverables/d-data/authority-mock.json#L613), [deliverables/d-data/authority-mock.json](../deliverables/d-data/authority-mock.json#L832)。

影响：这会直接阻断 D-data 作为“唯一权威 mock”的核心价值。交付本身存在，但当前程序壳仍然跑在旧 bootstrap 数据上，C/E 无法真正消费这次数据层成果。

### 2. 高优先级：当前装配结果仍然丢失 D-data 的公开端关键视图，说明集成链路与交付契约还没对齐

- D-data 的 manifest 把 `results`、`caStatuses` 等顶层键都声明为提供视图的一部分，见 [deliverables/d-data/handoff.manifest.json](../deliverables/d-data/handoff.manifest.json#L88)。
- 但当前装配后的 [runtime-data/assembled-view.json](../runtime-data/assembled-view.json#L19) 仍然是 `works: []`，而且没有把 D-data authority mock 里的 `results` 公开视图带进运行态。
- 同时 [scripts/assemble.js](../scripts/assemble.js#L81) 现在会把 `caStatuses` 改成依赖 B-admin 的 `ca-status.sample.json`，而不是优先承接 D-data / A-rider 提供的权威赛时状态来源。

影响：即使 D-data 交付本身准备好了多视图权威数据，当前运行态仍然拿不到这些关键内容，导致公开端、管理端和 screen 相关页面继续停留在弱数据或空数据模式。

## What Passed

- `deliverables/d-data/handoff.manifest.json` 已存在，`node scripts/validate-handoffs.js` 能正确发现 D-data 交付。
- `python generate.py` 可以成功生成 `authority-mock.json`、`relational-mock.json` 和 `seed.sql`。
- `python manage.py verify` 本地 12 条核心不变量全部通过，说明 generator 与 relational mock 内部一致性是成立的。
- 交付结构完整，不是“只给一个 JSON 就结束”：同时包含 [deliverables/d-data/authority-mock.schema.md](../deliverables/d-data/authority-mock.schema.md)、[deliverables/d-data/data-coverage-report.md](../deliverables/d-data/data-coverage-report.md)、[deliverables/d-data/data-mapping-notes.md](../deliverables/d-data/data-mapping-notes.md) 和 [deliverables/d-data/source/README.md](../deliverables/d-data/source/README.md)。

## Overall Assessment

- 如果只看“D-data 是否交出了可信、可生成、可校验的数据层产物”，答案是：**是，完成度较高**。
- 如果看“当前程序壳是否已经真正接入这次 D-data 交付”，答案是：**还没有**。
